# Bambu Control Bridge — גשר ביתי לשליטה מרחוק

גשר קטן שרץ על המחשב הביתי ומחבר את האפליקציה בטלפון למדפסת, **גם מחוץ לבית**. זה קוד שלנו (לא Bambuddy), עם רישיונות מתירניים, כדי שנוכל למכור אותו.

## למה צריך אותו
בבית, האפליקציה מדברת עם המדפסת ישירות. מחוץ לבית הטלפון לא מגיע לרשת הביתית, ולכן צריך "נציג" קבוע בבית שישמור על הקשר עם המדפסת ויעביר פקודות וסטטוס אל הטלפון, בצורה מאובטחת.

## ארכיטקטורה
```
טלפון (מחוץ לבית)  ──HTTPS/WebSocket (דרך Tailscale)──►  Bridge (מחשב בבית)
                                                             │  MQTT/TLS 8883  (סטטוס ופקודות)
                                                             │  FTPS 990       (העלאת קובץ הדפסה)
                                                             ▼
                                                      Bambu Lab A1 (LAN)
```

## רכיבים
| רכיב | מה הוא עושה | סטטוס |
|---|---|---|
| `src/bambu/commands.ts` | בניית פקודות ה-MQTT (pushall, pause/resume/stop, תאורה, התחלת הדפסה) | ✅ נבנה ונבדק |
| `src/bambu/report.ts` | פענוח דוחות הסטטוס מהמדפסת (מצב, אחוז, טמפרטורות, שכבה, שגיאות) | ✅ נבנה ונבדק |
| שכבת רשת: לקוח MQTT/TLS 8883 + FTPS 990 | החיבור בפועל למדפסת | ⏳ דורש את המדפסת לבדיקה |
| API מאובטח + צימוד (קוד/QR) + WebSocket | מה שהטלפון מתחבר אליו | ⏳ |
| אריזה "להורדה והרצה" + מדריך פשוט | כפתור אחד במחשב, קישור/QR לטלפון | ⏳ |

## שלבים
1. ✅ ליבת הפרוטוקול (פקודות + פענוח), עם בדיקות יחידה (`npm test`).
2. ⏳ חיבור LAN אמיתי: לקוח MQTT מעל TLS (self-signed), ו-FTPS עם שימוש חוזר ב-session. ייבדק מול ה-A1.
3. ⏳ שרת מקומי: צימוד מאובטח לטלפון (קוד חד-פעמי/QR), אימות, WebSocket לסטטוס חי.
4. ⏳ גישה מרחוק דרך Tailscale, בלי לפתוח פורטים בראוטר.
5. ⏳ אריזה: קובץ להורדה למחשב (Windows/Mac/Linux) שמריץ את הגשר, עם מדריך בעברית.

## בדיקות
```bash
cd services/bridge && npm test
```
(רץ עם מנוע הבדיקות המובנה של Node — בלי התקנות.)
